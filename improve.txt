RELIABILITY & ENGINE POLISH
=============================================================

[OPS-1] Rate limiting on execution endpoint
→ Per-user limit: 10 runs/minute via Redis token bucket.
→ Metric Impact: "Engineered a distributed token-bucket rate limiter using Redis to protect the C++ code execution engine from DDoS attacks and resource exhaustion, successfully capping execution requests at 10 req/min per user and ensuring 99.9% platform uptime."
→ Status: NOT STARTED

[ENGINE-2] Zero-Allocation Output Verification
→ Problem: Current string matching (`split.map.join.trim`) allocates 4+ new arrays/strings, causing massive GC overhead for large outputs.
→ Architecture: Implement a two-pointer string matching algorithm in Javascript to skip whitespace in-place without memory allocation.
→ Metric Impact: "Optimized execution engine output verification by engineering a zero-allocation, two-pointer string parsing algorithm, reducing V8 Garbage Collection overhead and decreasing evaluation memory footprint by up to 80% for megabyte-scale outputs."
→ Status: NOT STARTED

[UI-1] Myers Diff Algorithm for Visual Output Comparison
→ Problem: "Wrong Answer" is hard to debug without seeing exact character deviations.
→ Architecture: Run Myers Diff Algorithm on the frontend to render GitHub-style red/green character diffs.
→ Metric Impact: "Integrated the Myers diff algorithm into the frontend React IDE, generating real-time, character-by-character visual diffs for failed test cases, significantly reducing candidate debugging time."
→ Status: NOT STARTED
