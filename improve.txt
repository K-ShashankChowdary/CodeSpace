THE INTERVIEW PLATFORM PIVOT (CURRENT FOCUS)
=============================================================

[SOURCE CONTROL STRATEGY]
This project is undergoing a massive architectural rewrite from V1 (Classroom) to V2 (Interview Platform).
→ `main` branch: DO NOT use for active pivot development.
→ `v1-classroom` branch: The perfectly stable, completed Classroom app. Use this branch ONLY if a critical bug fix needs to be deployed to the legacy app or if you need to demonstrate the old app.
→ `v2-interview-pivot` branch: **Active Development Branch**. ALL work for the EPICS below must happen on this branch. We will merge back to `main` only when the V2 MVP is 100% complete and tested.

CodeSpace is pivoting from a 1-to-many "Classroom" tool to a 1-to-1 "Technical Interview" platform.
To complete the MVP for the resume, the following features must be executed:



[FEAT-2] Session Data Model & Guest Auth Flow
→ Problem: The current `Room` model is built for 50 students, and forces users to create an account to join.
→ Architecture: 
  1. Replace `room.model.js` with `session.model.js` (Interviewer, Candidate, Status, Code Snapshot).
  2. Implement Guest Join: Interviewer sends a link -> Candidate enters name -> Receives scoped JWT -> Drops instantly into IDE.
→ Done when: A candidate can join an active interview session in under 3 seconds without a password.

[FEAT-3] UI Overhaul: Dashboard to Interview View
→ Problem: `RoomDashboard.jsx` shows a grid of student tiles. This is useless for a 1:1 interview.
→ Architecture:
  1. Delete `RoomDashboard.jsx`.
  2. In `Dashboard.jsx`, rename "Host Classroom" to "Start Interview Session".
  3. In `IDE.jsx`, add an "Interviewer Mode" side-panel (only visible to the host) to take private notes and change the active problem.

[FEAT-4] Multi-language Support
→ Problem: Currently only C++ is hardcoded.
→ Architecture:
  1. Pull Docker images: `python:3.12-slim`, `openjdk:21-slim`, `node:20-slim`.
  2. Worker selects image + run command based on a new language dropdown in the editor.

[FEAT-5] Problem Bank & Test Case Runner
→ Problem: Interviewers paste questions in chat. Submissions only run against custom input.
→ Architecture:
  1. `Problem` model in MongoDB with hidden test cases.
  2. "Run" button executes sample cases. "Submit" executes all hidden cases and returns pass/fail metrics.

[FEAT-6] Built-in Video Call
→ Problem: Requires a separate Zoom link.
→ Architecture: Embed a Daily.co iframe into a resizable side panel next to the code editor.

[FEAT-7] Public Landing Page
→ Problem: The app has no public-facing page. Unauthenticated users hit the login form with zero context about what CodeSpace is.
→ Architecture:
  1. New route `/landing` (or `/`) for unauthenticated users — full-screen hero, feature highlights, and CTA.
  2. Sections: Hero (headline + CTA), Features (collaborative editor, real-time verdict, problem bank), How It Works, and Footer.
  3. CTA "Start Interviewing" links to `/auth`.
  4. Scroll-driven animations for section reveals, glassmorphism panels, neon accents matching the app's dark theme.
→ Done when: A recruiter can land on the page, understand the product in 10 seconds, and click through to sign up.
